# 41. Lab: Enable HTTP/2 Protocol

## Overview

This lab demonstrates how to switch an NGINX website from **HTTP/1.1 to HTTP/2**.

The process involves:

1. Checking the HTTP protocol currently used by the website.
2. Inspecting the existing NGINX build configuration.
3. Rebuilding NGINX with the HTTP/2 module.
4. Verifying that the HTTP/2 module is included.
5. Adding HTTP/2 to the NGINX configuration.
6. Reloading NGINX.
7. Verifying that browser requests now use HTTP/2.
8. Restarting NGINX if a reload does not apply the change.

---

# 1. Check the Current HTTP Protocol

Before making any changes, verify which HTTP version the website is currently using.

Open the website in a browser such as Firefox.

Then:

1. Press `F12` to open Developer Tools.
2. Select the **Network** tab.
3. Refresh the website.
4. Select one of the requests.

For example, select a JavaScript request.

The request information shows that the website is currently using:

```text
HTTP/1.1
```

The lecture also points out other request information such as:

- Connection type: `keep-alive`
- Date
- ETag
- Last-Modified

The important information for this lab is the HTTP protocol version.

---

# 2. Determine How NGINX Was Built

To enable HTTP/2, the lecture demonstrates rebuilding NGINX with the required HTTP/2 module.

First, inspect the configuration options used to build the currently running NGINX installation.

Run:

```bash
nginx -V
```

The command displays the configuration arguments used when NGINX was compiled.

### Important

Save the existing configuration parameters somewhere safe.

The reason is that when rebuilding NGINX, the existing configuration options should be preserved, with the HTTP/2 module
added to them.

---

# 3. Locate the NGINX Source Directory

Navigate to the directory where the NGINX source code was extracted.

The lecture refers to the NGINX source directory as the location containing the `configure` script.

For example:

```text
nginx/
├── configure
├── src/
├── auto/
└── ...
```

The exact source directory depends on where NGINX was extracted on the system.

---

# 4. Inspect the Available HTTP Modules

From the NGINX source directory, the lecture searches the available configuration options for HTTP-related modules.

The `configure` script provides the available build options.

The important option identified in the lecture is the **HTTP/2 module**.

The lecture refers to the option as:

```text
--with-http_v2_module
```

This module needs to be included when rebuilding NGINX.

---

# 5. Reconfigure NGINX with HTTP/2

Run the NGINX `configure` script again.

The important rule is:

> **Preserve the existing configuration parameters and add the HTTP/2 module option.**

The general structure is:

```bash
./configure \
    <existing-configure-options> \
    --with-http_v2_module
```

The `<existing-configure-options>` represent the options obtained earlier from:

```bash
nginx -V
```

The lecture emphasizes that the previous build parameters should be retained rather than replacing the existing NGINX
build configuration with an unrelated configuration.

---

# 6. Compile NGINX

After the `configure` command completes successfully, compile NGINX.

Run:

```bash
make
```

The compilation can take some time.

Wait for the process to complete.

---

# 7. Install the New NGINX Build

After compilation completes, install the newly built NGINX.

Run:

```bash
make install
```

Once the installation completes, verify that NGINX is still running.

The lecture uses:

```bash
ps -ef | grep nginx
```

The NGINX processes should be displayed.

---

# 8. Verify the HTTP/2 Module

Now run:

```bash
nginx -V
```

Inspect the output.

The HTTP/2 module should now be present in the build configuration.

The important result is that NGINX was built with:

```text
--with-http_v2_module
```

This confirms that the installed NGINX build contains HTTP/2 support.

> **Important distinction:** Having the HTTP/2 module compiled into NGINX does not automatically mean that the website
> is using HTTP/2. The module must also be enabled in the NGINX server configuration.

---

# 9. Enable HTTP/2 in `nginx.conf`

Now modify the NGINX configuration file:

```bash
vi /etc/nginx/nginx.conf
```

The lecture's existing configuration already uses SSL/HTTPS.

In the `listen` directive, add the HTTP/2 parameter after `ssl`.

The configuration becomes:

```nginx
server {
    listen 443 ssl http2;

    # Other configuration...
}
```

The important change is:

```nginx
http2
```

added to the `listen` directive.

Conceptually:

```text
Before:
listen 443 ssl;

After:
listen 443 ssl http2;
```

This tells NGINX to enable HTTP/2 for that HTTPS listener.

---

# 10. Validate the NGINX Configuration

Before applying the new configuration, verify that the configuration is valid.

Run:

```bash
nginx -t
```

The configuration should pass the syntax/configuration test.

Only proceed with the reload/restart after the configuration is valid.

---

# 11. Verify the Protocol Before Reloading

Before reloading NGINX, refresh the website again and inspect a request.

The browser should still report:

```text
HTTP/1.1
```

This confirms that simply compiling NGINX with HTTP/2 support has not yet switched the website to HTTP/2.

The protocol changes only after HTTP/2 is enabled in the NGINX configuration and the new configuration is applied.

---

# 12. Reload NGINX

Apply the new configuration by reloading NGINX.

The lecture refers to the NGINX reload operation:

```bash
nginx -s reload
```

After the reload, return to the browser.

The lecture then opens the website in a new tab and opens the Network Developer Tools.

---

# 13. Verify HTTP/2

Refresh/open the website and inspect the requests in the Network tab.

The page may contain requests for resources such as:

- CSS files
- PNG files
- JPG files
- JavaScript files

Open any request.

The HTTP protocol version should now show:

```text
HTTP/2
```

For example:

```text
CSS request → HTTP/2
JPG request → HTTP/2
JavaScript request → HTTP/2
```

The important point is that the requests are no longer being served using:

```text
HTTP/1.1
```

but instead:

```text
HTTP/2
```

---

# 14. If Reload Is Not Enough

The instructor provides an important troubleshooting note.

In some situations, an NGINX reload may not be sufficient for the change to appear.

If the browser continues to show:

```text
HTTP/1.1
```

after the configuration has been changed and reloaded, restart the NGINX service.

Run:

```bash
systemctl restart nginx
```

Then test the website again.

The lecture notes that behavior can depend on the NGINX version/environment: some installations accept the reload, while
others may require a service restart for the expected behavior to appear.

# Key Configuration

The essential NGINX configuration demonstrated in this lab is:

```nginx
server {
    listen 443 ssl http2;

    # SSL certificate configuration
    ssl_certificate /etc/nginx/ssl/self.cert;
    ssl_certificate_key /etc/nginx/ssl/self.key;

    # Other server configuration...
}
```

The important part for this lecture is:

```nginx
listen 443 ssl http2;
```

# Common Mistakes / Warnings

### 1. Compiling the module is not enough

Adding:

```text
--with-http_v2_module
```

to the NGINX build only provides HTTP/2 support.

You must also enable HTTP/2 in the server configuration:

```nginx
listen 443 ssl http2;
```

---

### 2. Forgetting the existing configure options

When rebuilding NGINX, don't discard the configuration options from the existing build.

First run:

```bash
nginx -V
```

Save the existing options, then add the HTTP/2 module option to the configuration.

---

### 3. Not testing the configuration

Always validate the configuration before applying it:

```bash
nginx -t
```

---

### 4. Reload does not reflect the change

If the browser still reports HTTP/1.1 after the reload, restart NGINX:

```bash
systemctl restart nginx
```

Then verify the protocol again.

---

# Final Takeaway

The lab demonstrates that enabling HTTP/2 in NGINX requires **two stages**:

**Stage 1 — Build support**

Compile NGINX with:

```text
--with-http_v2_module
```

**Stage 2 — Enable the protocol**

Configure the HTTPS listener with:

```nginx
listen 443 ssl http2;
```

After applying the configuration, browser Developer Tools can be used to verify that individual requests are now being
served through **HTTP/2 instead of HTTP/1.1**.
