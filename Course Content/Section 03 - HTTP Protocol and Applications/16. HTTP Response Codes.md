# 16. HTTP Response Codes

## Lecture Title

**HTTP Response Codes**

## Overview

Whenever a client submits an HTTP request to a web server, the server returns a **response**. Along with that response,
the server provides an **HTTP response code**, also called a **status code**.

The response code tells the client about the status of the request, such as whether the request:

- Is being processed
- Was successfully completed
- Requires redirection
- Contains an error on the client side
- Encountered a server-side error

HTTP response codes are **three-digit integers**, and the **first digit determines the class/category** of the response.

---

# 1. Purpose of HTTP Response Codes

When a web client sends a request, the client needs a way to determine what happened to that request.

For example:

```text
Client
   |
   | HTTP Request
   v
Web Server
   |
   | HTTP Response + Status Code
   v
Client
```

The response code provides information about the status of the request.

It can indicate whether the request was:

- Received
- Successfully processed
- Redirected
- Rejected
- Not fulfilled
- Affected by a client error
- Affected by a server error

The client or another component can then use the status code to determine what further processing should take place.

---

# 2. HTTP Status Code Structure

An HTTP status code is a **three-digit integer**.

The **first digit** identifies the class of the response.

```text
+-------------------+
| 1 | X | X         |
+-------------------+
  ^
  |
Response class
```

The five major classes are:

| First Digit | Class         | Meaning                                                 |
|-------------|---------------|---------------------------------------------------------|
| `1xx`       | Informational | Request received; processing continues                  |
| `2xx`       | Success       | Request successfully received/understood/accepted       |
| `3xx`       | Redirection   | Further action/redirection is required                  |
| `4xx`       | Client Error  | Problem with the client request                         |
| `5xx`       | Server Error  | Server encountered a problem fulfilling a valid request |

The lecture organizes HTTP response codes around these five categories.

---

# 3. `1xx` — Informational Responses

A response beginning with **`1`** is an informational response.

Examples mentioned in the lecture include:

```text
100
101
102
103
104
```

The important concept from the lecture is:

> The request has been received and processing is continuing.

Conceptually:

```text
Client
   |
   | Request
   v
Server
   |
   | 1xx
   v
"Request received; processing continues"
```

A `1xx` response therefore indicates that the request has not reached its final result yet.

---

# 4. `2xx` — Successful Responses

A response beginning with **`2`** indicates successful processing.

Examples mentioned include:

```text
200
201
203
204
205
```

The lecture describes this category as meaning that the request was:

- Successfully received
- Understood
- Accepted

Conceptually:

```text
Client
   |
   | Request
   v
Server
   |
   | 2xx
   v
"Request successfully processed"
```

### Common examples

#### `200`

The lecture identifies `200` as a common successful response.

It indicates that the request was successful.

#### `201`

The lecture identifies `201` as indicating that a **resource was created**.

---

# 5. `3xx` — Redirection Responses

A response beginning with **`3`** indicates **redirection**.

Examples mentioned in the lecture include:

```text
300
301
302
304
```

The lecture explains that a `3xx` response means that **further action must be taken to complete the request**.

The request is therefore not simply completed at the current location; the client may need to follow a redirection.

Conceptually:

```text
Client
   |
   | Request
   v
Server A
   |
   | 3xx Redirect
   v
Server / Resource B
   |
   | Response
   v
Client
```

### `301` — Moved Permanently

The lecture specifically demonstrates **`301 Moved Permanently`** using Yahoo.

A browser request can receive:

```text
301 Moved Permanently
```

The browser then follows the redirection to another URL.

---

# 6. `4xx` — Client Error

A response beginning with **`4`** represents a **client error**.

The lecture explains that this means the HTTP request contains an issue that prevents the server from fulfilling it.

Examples mentioned include:

```text
400
401
403
404
```

The lecture's general description is that the request may contain incorrect information/syntax or may refer to something
the server cannot process.

Conceptually:

```text
Client
   |
   | Invalid / problematic request
   v
Server
   |
   | 4xx
   v
Client Error
```

---

## 6.1 Common `4xx` Codes

### `400`

The lecture identifies `400` as a common client-error response.

It indicates a problem with the request.

### `401`

The lecture identifies `401` with **unauthenticated** access.

It is associated with a request that requires authentication.

### `403`

The lecture identifies `403` as **access forbidden**.

### `404`

The lecture identifies `404` as:

**Page Not Found**

This is one of the most commonly encountered HTTP response codes.

For example:

```text
404 Not Found
```

can occur when a requested resource cannot be found.

---

# 7. `5xx` — Server Error

A response beginning with **`5`** indicates a **server-side error**.

The lecture explains that the request itself can be valid, but the server cannot fulfill it.

Conceptually:

```text
Client
   |
   | Valid Request
   v
Server
   |
   | Unable to fulfill request
   v
5xx Server Error
```

---

## 7.1 Difference Between `4xx` and `5xx`

This is an important distinction emphasized in the lecture.

### `4xx`

The problem is associated with the **client request**.

The lecture describes the situation as the server not being able to accept or understand the request.

```text
4xx
 ↓
Client-side request problem
```

### `5xx`

The request is considered valid, but the **server cannot fulfill it**.

```text
5xx
 ↓
Server-side processing problem
```

The lecture gives the common example:

### `500`

**Internal Server Error**

This indicates a server-side failure while processing the request.

# 12. Multiple Requests Can Have Different Status Codes

A single web page can generate many HTTP requests.

For example:

```text
Browser
   |
   +--> Request 1 --> 301
   |
   +--> Request 2 --> 200
   |
   +--> Request 3 --> 200
   |
   +--> Request 4 --> 404
   |
   +--> Request 5 --> 200
```

Therefore, when troubleshooting a web application, it is important to inspect the status code of the **individual
request**, rather than assuming that the entire page has only one status code.

# 13. HTTP Response Code Classification

The overall classification can be remembered using the first digit:

```text
1xx → Informational
2xx → Success
3xx → Redirection
4xx → Client Error
5xx → Server Error
```

A useful mental model is:

```text
        HTTP Status Code
               |
     +---------+---------+
     |         |         |
    1xx       2xx       3xx
     |         |         |
  Info      Success   Redirect
     
     +---------+---------+
     |                   |
    4xx                 5xx
     |                   |
Client Error        Server Error
```

# Practical Notes for Nginx

HTTP response codes are particularly useful when troubleshooting **Nginx**.

When a client sends a request through Nginx, inspecting the returned status code can immediately indicate the general
category of the result:

```text
Request
   |
   v
Nginx / Web Server
   |
   v
HTTP Status Code
```

For example:

- `2xx` → the request was successfully handled.
- `3xx` → investigate the redirection behavior.
- `4xx` → investigate the client request, requested resource, authentication, or access conditions.
- `5xx` → investigate server-side processing and upstream/application failures.

The exact cause still requires examining the specific status code and the surrounding request/server logs.

---

# Common Mistakes / Warnings

### 1. Looking only at the page instead of individual requests

A web page can make many HTTP requests. One request can succeed while another fails.

Use the browser's **Network** tools to inspect individual requests.

### 2. Treating all error codes as the same

`4xx` and `5xx` represent different categories:

```text
4xx → Client/request-side problem
5xx → Server-side problem
```

### 3. Ignoring `3xx` responses

A `3xx` response is not necessarily a failure. It indicates that **redirection/further action is involved**.

For example:

```text
301 Moved Permanently
```

can cause the browser to request another URL.

---

# Lecture Takeaway

The most important concept from this lecture is:

> **HTTP response codes describe the status of an HTTP request.**

Every HTTP response contains a three-digit status code, and the **first digit identifies the response class**:

```text
1xx → Informational
2xx → Successful
3xx → Redirection
4xx → Client Error
5xx → Server Error
```

When working with Nginx, these codes are essential for understanding what happened to a request and are one of the first
things to inspect when troubleshooting HTTP traffic.
