# 13. Types of Protocols

## Lecture Title

**Types of Protocols**

## Overview

When working with **Nginx**, it is important to understand how the **HTTP protocol** works because Nginx is a web
server. Understanding HTTP requires familiarity with:

- What a protocol is
- Why protocols are required for communication
- Different types of network protocols
- How protocols facilitate communication between machines
- The relationship between protocols such as TCP and IP
- The purpose of HTTP and HTTPS in web communication

A **protocol** can be understood as a **digital language** through which machines communicate with each other over the
Internet.

# 1. What Is a Protocol?

A protocol is a **digital language** used by machines to communicate over a network or the Internet.

### Human-language analogy

Humans use different languages to communicate. For example:

- English
- Spanish
- Russian
- Hindi
- Sanskrit
- Urdu
- Japanese

Communication between two people is possible when both parties understand a common language.

For example, if:

- One person speaks only English
- Another person speaks only Japanese

then they cannot directly communicate unless they share another language that both understand.

Network protocols work similarly.

A protocol provides a **common set of rules and language** that allows different machines to communicate.

> In simple terms, a protocol can be thought of as a language used for communication between machines.

---

# 2. Formal Definition of a Protocol

The lecture gives the following conceptual definition:

A protocol is a **set of mutually accepted and implemented rules at both ends of a communication channel for the proper
exchange of information**.

In computer communication, machines need rules that define how information is transferred.

The communication process can involve:

- Rules
- Checks
- Limitations
- Data-transfer requirements

Therefore, both sides of a communication channel must follow the appropriate protocol so that information can be
exchanged correctly.

### Communication model

Conceptually:

```text
Sender
   |
   | Message/Data
   v
Protocol / Communication Medium
   |
   | Message/Data
   v
Receiver
```

The protocol provides the rules that allow the sender and receiver to understand how information should be exchanged.

---

# 3. Different Protocols Have Different Purposes

There are multiple protocols in computer networking.

Each protocol:

- Has a specific purpose
- Has its own rules
- Is identified by a unique name
- Is designed for particular types of communication

For example:

- TCP is used for network communication.
- IP helps route packets through networks.
- SMTP is used for sending email.
- POP/POP3 is used for receiving email.
- FTP is used for file transfer.
- HTTP is used for web communication.
- HTTPS provides the secure version of HTTP.

Therefore, the protocol used depends on the type of communication that needs to take place.

# 4. Common Protocols

The lecture introduces the following protocols.

## 4.1 Transmission Control Protocol (TCP)

**TCP** stands for **Transmission Control Protocol**.

TCP is described as a popular communication protocol used for communication over a network.

### How TCP works

When communication occurs using TCP, the message is divided into a series of **packets**.

Conceptually:

```text
Complete Message
       |
       v
+------+------+------+------+
| Pkt1 | Pkt2 | Pkt3 | Pkt4 |
+------+------+------+------+
       |
       v
    Network
       |
       v
+------+------+------+------+
| Pkt1 | Pkt2 | Pkt3 | Pkt4 |
+------+------+------+------+
       |
       v
Reassembled Message
```

The packets are sent from the source toward the destination.

At the destination, the packets are **reassembled** to recreate the complete message.

The lecture presents TCP as one of the important protocols involved in the communication process.

---

# 5. Internet Protocol (IP)

**IP** stands for **Internet Protocol**.

The lecture explains that **TCP and IP work together**.

While TCP handles the communication and packetization process, IP helps with **routing the packets through the
network**.

### Routing through network nodes

A packet may need to travel through multiple network nodes before reaching its destination.

Conceptually:

```text
Source
  |
  v
Node 1
  |
  v
Node 2
  |
  v
Node 3
  |
  v
Destination
```

The IP protocol, using the IP address information in the packet, helps determine where the packet should be routed.

Therefore:

```text
TCP + IP
   |
   +--> TCP: communication / packet handling
   |
   +--> IP: routing toward the destination
```

The lecture emphasizes that TCP and IP work together to establish network communication.

---

# 6. User Datagram Protocol (UDP)

**UDP** stands for **User Datagram Protocol**.

The lecture describes UDP as an alternative/substitute communication protocol to TCP.

UDP is intended for creating communication links between applications with:

- Low overhead
- Low latency

The lecture contrasts UDP with TCP and explains that they can be used in similar communication scenarios, while UDP is
selected when low latency and low tolerance for overhead are important.

### TCP vs. UDP — according to the lecture

| TCP                                  | UDP                                        |
|--------------------------------------|--------------------------------------------|
| Commonly used communication protocol | Alternative to TCP                         |
| Used for network communication       | Used when low latency is desired           |
| Provides packet-based communication  | Focuses on lower overhead/latency          |
| Described as more commonly used      | Used for specific low-latency requirements |

The lecture notes that TCP is generally more commonly used, while UDP can be appropriate when low latency is required.

# 7. Post Office Protocol (POP / POP3)

**POP** or **POP3** stands for **Post Office Protocol**.

Its purpose is to **receive incoming emails**.

The lecture specifically mentions POP/POP3 in the context of email communication.

Conceptually:

```text
Mail Server
     |
     | Incoming Email
     v
POP / POP3
     |
     v
Email Client
```

POP/POP3 is therefore associated with receiving email messages.

---

# 8. Simple Mail Transfer Protocol (SMTP)

**SMTP** stands for **Simple Mail Transfer Protocol**.

SMTP is used to **send and distribute outgoing emails**.

For example, enterprise applications commonly need to send emails for features such as:

- Forgot-password functionality
- Subscription emails
- Other customer notifications

In such scenarios, an application can use an **SMTP server** configured to send and distribute emails to customers.

Conceptually:

```text
Web Application
      |
      | SMTP
      v
SMTP Server
      |
      | Outgoing Email
      v
Customer
```

### Example: Forgot Password

A web application may provide a "Forgot Password" feature.

The application needs to send an email containing the relevant password-reset information. The application can
communicate with an SMTP server, which handles the outgoing email delivery.

# 9. File Transfer Protocol (FTP)

**FTP** stands for **File Transfer Protocol**.

FTP is a well-known protocol used to **transfer files from one machine to another**.

The lecture describes FTP in the context of transferring files between machines, including communication over LAN
environments.

Conceptually:

```text
Machine A
    |
    | FTP
    | File Transfer
    v
Machine B
```

FTP is therefore associated with file-transfer operations.

# 10. Hypertext Transfer Protocol (HTTP)

**HTTP** stands for **Hypertext Transfer Protocol**.

The lecture identifies HTTP as the main protocol used for **web communication**.

HTTP works using a **client-server model**.

### HTTP client-server model

```text
Web Client
    |
    | HTTP Request
    v
Web Server
    |
    | HTTP Response
    v
Web Client
```

HTTP is used to establish communication between:

- A web client
- A web server

The lecture also explains that HTTP is involved when information is served through web pages.

Therefore, whenever working with the **Web**, HTTP is a fundamental protocol to understand.

This is particularly relevant to Nginx because **Nginx is commonly used as a web server**, meaning it handles HTTP-based
web traffic.

---

# 11. Hypertext Transfer Protocol Secure (HTTPS)

**HTTPS** stands for **Hypertext Transfer Protocol Secure**.

HTTPS is described as the **secure version of HTTP**.

For example, when accessing websites such as:

- Facebook
- Twitter
- YouTube

the address can use the HTTPS scheme:

```text
https://facebook.com
```

The `https://` portion indicates that the connection is using HTTPS.

---

## 11.1 HTTP vs. HTTPS

The lecture identifies the primary difference as **encryption of data transmitted over the network**.

With HTTPS, the data transmitted between the client and server is encrypted.

Conceptually:

### HTTP

```text
Client
  |
  | HTTP
  | Data
  v
Server
```

### HTTPS

```text
Client
  |
  | HTTPS
  | Encrypted Data
  v
Server
```

The lecture notes that some websites may support both HTTP and HTTPS, while many websites use HTTPS because it provides
a more secure communication channel.

# 12. Summary of the Protocols

The protocols covered in this lecture can be summarized as follows:

### TCP — Transmission Control Protocol

Used for communication over a network. The lecture explains that TCP divides a message into packets, sends them toward
the destination, and reassembles them at the destination.

### IP — Internet Protocol

Works together with TCP and helps route packets through different network nodes toward their destination.

### UDP — User Datagram Protocol

An alternative to TCP that is useful when low overhead and low latency are desired.

### POP / POP3 — Post Office Protocol

Used for receiving incoming email.

### SMTP — Simple Mail Transfer Protocol

Used for sending and distributing outgoing email, including emails generated by enterprise applications.

### FTP — File Transfer Protocol

Used to transfer files between machines.

### HTTP — Hypertext Transfer Protocol

Used for web communication between web clients and web servers. It follows the client-server model.

### HTTPS — Hypertext Transfer Protocol Secure

The secure version of HTTP. The lecture explains that transmitted data is encrypted when HTTPS is used.

# Practical Notes / Best Practices

- When working with **Nginx as a web server**, understanding HTTP is essential.
- Network communication requires both sides to follow a common protocol.
- Different protocols solve different communication requirements.
- TCP and IP are commonly used together: TCP handles the communication mechanism while IP assists with routing.
- UDP is relevant when low latency and low overhead are important.
- SMTP is particularly relevant to web applications that need to send automated emails.
- HTTP is the core protocol to understand when working with web servers.
- HTTPS adds encryption to HTTP communication and is therefore used for secure web communication.
