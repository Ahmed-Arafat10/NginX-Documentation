# 27. Lab - Add Modules in NGINX

## Overview

This lab demonstrates how to add a **dynamic module** to an NGINX installation that was originally built from source.

The lab uses the **NGINX HTTP Image Filter module** as an example. The overall process is:

1. Inspect the existing NGINX build configuration.
2. Identify available dynamic modules.
3. Reconfigure NGINX with the desired module.
4. Install any required external library.
5. Build and install NGINX again.
6. Verify that the dynamic module was installed.
7. Configure NGINX to load the `.so` module.
8. Use a directive provided by the module.
9. Test the module with an actual image.
10. Troubleshoot browser caching when configuration changes are not immediately visible.

---

# 1. Inspect the Existing NGINX Installation

The lab starts with an NGINX installation that was previously built from source.

First, inspect the NGINX configuration directory:

```bash
cd /etc/nginx
ls
```

The instructor checks whether a `modules` directory exists.

If the directory is not present, it indicates that the current installation does not yet have the handcrafted
dynamic-module directory being demonstrated in the lab.

---

# 2. Inspect the Existing Build Configuration

When NGINX is compiled from source, the configuration options used during the build are important.

Run:

```bash
nginx -V
```

The uppercase `-V` displays NGINX build information, including the configure arguments used to build the current
installation.

The lab copies these configure arguments because they need to be preserved when rebuilding NGINX with an additional
module.

Conceptually:

```text
Existing NGINX build
        │
        ▼
nginx -V
        │
        ▼
Existing configure arguments
        │
        ▼
Reuse + add new module
```

---

# 3. Inspect Available Dynamic Modules

Navigate to the NGINX source directory used previously in the course and inspect the available configuration options.

The lab uses a command equivalent to:

```bash
./configure --help
```

This displays the modules and configuration options supported by the source tree.

The instructor then filters the output to identify dynamic modules:

```bash
./configure --help | grep dynamic
```

The output includes several dynamic modules, such as:

- XSLT
- Image Filter
- GeoIP
- Perl
- Mail
- Stream
- Other optional modules

The purpose of this step is to identify a module that can be added to the NGINX build.

---

# 4. Add the Image Filter Dynamic Module

The lab chooses the **Image Filter** module.

When configuring NGINX again, the original configure arguments are retained and an additional module configuration
option is added.

The module is configured as a dynamic module and its output is directed to:

```text
/etc/nginx/modules
```

The important configuration concept is:

```text
Existing configure arguments
        +
Image Filter dynamic module
        +
modules-path=/etc/nginx/modules
```

The exact configure command used in this lab is:

```bash
./configure --sbin-path=/usr/bin/nginx --conf-path=/etc/nginx/nginx.conf --error-log-path=/var/log/nginx/error.log --http-log-path=/var/log/nginx/access.log --with-pcre --pid-path=/var/run/nginx.pid --with-http_ssl_module --with-http_image_filter_module=dynamic --modules-path=/etc/nginx/modules
```

The exact configure command depends on the arguments used by the original NGINX build.

---

# 5. Resolve the Image Filter Dependency

When the module is first added, the configuration process reports a dependency error.

The Image Filter module requires the **GD library**.

The lab installs the required development package:

```bash
apt-get update
apt-get install libgd-dev
```

Confirm the installation when prompted.

After the library installation completes, run the NGINX configuration command again.

This time, the configuration completes successfully.

### Important troubleshooting pattern

When adding a source module:

```text
Configure
   │
   ├── Dependency missing?
   │       │
   │       └── Install required development library
   │
   └── Configure successfully
```

A module may therefore require additional system libraries before NGINX can compile it.

---

# 6. Compile the Updated NGINX

After successful configuration, compile the source:

```bash
make
```

The compilation may take some time.

Wait until the `make` process completes successfully.

---

# 7. Install the Updated Configuration

After compilation finishes, install the newly built components:

```bash
make install
```

The lab uses this to install the new dynamic module alongside the existing NGINX installation.

NGINX is then checked to ensure that the process is still running:

```bash
ps -ax
```

---

# 8. Verify the Dynamic Module Installation

Run:

```bash
nginx -V
```

The output should now show the new module configuration and the configured module path.

The lab then checks the NGINX configuration directory:

```bash
cd /etc/nginx
ls
```

A new directory should now exist:

```text
modules
```

Enter the directory:

```bash
cd /etc/nginx/modules
ls
```

The newly compiled module should be present as an `.so` file.

For example, the Image Filter module appears as an NGINX Image Filter shared-object file.

The `.so` file is a compiled binary module, so its contents are not normally readable as plain text configuration.

---

# 9. Verify the Existing Image

Before configuring the Image Filter module, the lab identifies an image already being served by the website.

The instructor navigates through the site's directories, for example:

```text
blogging/
└── assets/
    └── images/
        └── about/
```

The image directory contains files such as:

- Welcome banner
- Profile image
- JPEG images

The complete URL/path to one of these images is then opened in the browser.

For example:

```text
<site>/.../welcome-banner.jpg
```

The image loads normally before applying the Image Filter transformation.

This provides a baseline for testing the module.

---

# 10. Find the Module's Configuration Directives

Installing a dynamic module does not automatically mean that its directives are known to NGINX configuration processing.

The lab therefore consults the NGINX documentation for the **HTTP Image Filter module**.

The Image Filter module provides directives such as:

```text
image_filter off
image_filter test
image_filter size
image_filter rotate
image_filter resize
image_filter crop
```

The lab chooses the `rotate` directive.

---

# 11. Configure an Image Filter Location

A dedicated location is created for the image being tested.

Conceptually:

```nginx
location = /path/to/image.jpg {
    image_filter rotate 180;
}
```

The exact image path comes from the existing website.

The purpose is to apply an Image Filter operation when NGINX receives a request for that particular image.

---

# 12. The `unknown directive` Error

After adding the Image Filter directive, the instructor tests the configuration:

```bash
nginx -t
```

NGINX reports an error similar to:

```text
unknown directive "image_filter"
```

This happens even though the Image Filter module has already been compiled.

The important distinction is:

```text
Module compiled
      ≠
Module loaded
```

NGINX must be explicitly told to load the dynamic module before its directives can be used.

---

# 13. Load the Dynamic Module

Dynamic modules are loaded using the `load_module` directive.

The directive is placed in the **global/main context**, outside the `http` and `server` blocks.

For example:

```nginx
load_module /etc/nginx/modules/ngx_http_image_filter_module.so;
```

The path must point to the `.so` file created during the module installation.

The lab verifies the actual filename with:

```bash
cd /etc/nginx
ls
cd modules
ls
```

The resulting module filename is then used in the `load_module` directive.

Conceptually:

```text
/etc/nginx/
├── nginx.conf
└── modules/
    └── ngx_http_image_filter_module.so
```

And in the global configuration:

```nginx
load_module /etc/nginx/modules/ngx_http_image_filter_module.so;
```

---

# 14. Validate the Configuration

After adding `load_module`, test the NGINX configuration:

```bash
nginx -t
```

The configuration should now pass validation.

The important troubleshooting sequence is:

```text
nginx -t
   │
   └── unknown directive
          │
          ▼
      Dynamic module not loaded
          │
          ▼
      Add load_module
          │
          ▼
      nginx -t
          │
          ▼
      Configuration OK
```

---

# 15. Reload NGINX

Once the configuration validates successfully, reload NGINX:

```bash
nginx -s reload
```

The reload applies the new configuration without requiring a complete NGINX restart.

---

# 16. Test the Image Filter Module

Return to the browser and request the configured image.

The configuration in the lab applies a 180-degree rotation:

```nginx
image_filter rotate 180;
```

The image should now appear rotated by 180 degrees.

This confirms that:

1. The Image Filter module was compiled.
2. The module was installed.
3. The module was loaded with `load_module`.
4. The Image Filter directive was accepted.
5. NGINX applied the transformation to the requested image.

---

# 17. Change the Image Rotation

The lab then modifies the configuration to test another rotation.

For example:

```nginx
image_filter rotate 270;
```

After saving the configuration, reload NGINX:

```bash
nginx -s reload
```

Then request the image again.

---

# 18. Browser Cache Can Hide Configuration Changes

The instructor observes that the browser may continue displaying the previous version of the image even after NGINX has
been reloaded.

This can happen because the browser has cached the previous response.

For example:

```text
NGINX configuration
      │
      ▼
image_filter rotate 270
      │
      ▼
Browser requests image
      │
      ▼
Cached image returned/displayed
```

The updated NGINX configuration may therefore be working even though the browser appears not to reflect the change.

---

# 19. Troubleshoot Browser Caching

The lecture recommends several ways to force a fresh request:

### Clear browser history/cache

Clear the relevant browser cache and request the image again.

### Clear cookies/history as demonstrated in the lecture

The instructor recommends clearing browser history and cookies when the transformed image does not appear to update.

### Use another browser

Open the image in another browser to avoid using the existing browser's cached copy.

### Use Incognito/Private mode

The lab demonstrates opening Firefox in Incognito mode and requesting the image again.

After doing so, the updated 270-degree rotation becomes visible.
